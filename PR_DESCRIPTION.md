# Alpenglow branch engine, V2 AccountsDB, and block production

This branch uses execute-on-receipt replay, certificate-gated durability, and batched log-structured folds in Alpenglow mode. Its V2 AccountsDB runtime is currently Alpenglow-only and rejects the unsafe classic per-slot persistence path; use the `dev` branch for `mainnet-beta`, `testnet`, or `devnet`. Alpenglow validator mode additionally wires TPU ingress, scheduled leader production, turbine broadcast, and replay verification of locally produced blocks.

## Base: the Alpenglow fork-choice layer (koro)

This branch builds on koro's `alpenglow-fork-choice` work (which supersedes the earlier `smcio/alpenglow` experimentation that contributed the initial Alpenglow scaffolding plus the native turbine/gossip/repair path). Koro's layer provides:

- **ChainTracker** — the certificate-driven decision core: block/skip/conflict decisions per the whitepaper's safety lemmas (unique-strength certs, finalized-ancestry derivation, indirect skips, conflict = halt with write-once evidence).
- **Certificate verification** — aggregate BLS over base2/base3 signer bitmaps, validator-set/stake checking, and the Agave votor wire codec validated against `agave-votor-messages` fixtures.
- **Votor QUIC receiver** for live vote/cert traffic, block-id hints into the turbine assembler, and the exact-BlockKey **promotion gate** with restart evidence.

## What this PR adds — part 1: the branch engine (ten logical units)

1. **Alpenglow protocol path** — replaces `pkg/forkchoice` and buffered/confirmation-gated execution with certificate fork choice and execute-on-receipt speculative replay; this V2 runtime rejects classic clusters before startup side effects.
2. **Wear-first durable store + WorkingSet** — K-slot union-deduped batch folds (one sequential segment, one fsync, one atomic index flip); the fold manifest doubles as commit record, index redo log (WAL-off capable), undo-pointer log, and resume-context carrier, so recovery rebuilds the durable frontier from the store itself (kill −9 no longer forces re-bootstrap). Undo pointers enable **rewind to any retained fold boundary** and a pinned, budgeted **compactor**. In RAM, the WorkingSet holds the unrooted suffix with a per-slot undo journal (fork switch = evict + re-execute; model-tested).
3. **Certificate pool** — local cert assembly from raw votes at Agave parity (thresholds, unions, vote budgets, fallback-only base3 assembly, disjointness; cross-checked against `anza-xyz/alpenglow` votor sources and SIMD-0326). Hard trust boundary: unverified votes never touch dedupe/equivocation/tally state. Verification is lazy-batched (one pairing per same-payload tally) but **always trigger-fresh**: tallies fold the moment any Votor fallback-trigger predicate (SafeToNotar/SafeToSkip, transcribed from Agave) could pass — one fold policy for observer and future voting nodes alike.
4. **Block source** — certified rewind for fork switches, mode-independent certified skips, and a cert-driven repair loop that steers turbine toward the most decisive certified-but-unobserved block per slot.
5. **Execute-on-receipt replay** — the switch sweep (executed identity vs decisive certs, gated on a decision version that also advances on replay-derived decisiveness), in-RAM unwind with guarded fallbacks, and the **dual watermark**: folds ≤ min(certificate finality, trailing-verifier watermark). Alpenglow certs attest block *data*, not execution, so a trailing verifier re-derives per-tx digests from finalized RPC blocks and is the execution-correctness oracle; divergence = evidence + halt; loop and shutdown share one gated fold path.
6. **Node wiring** — protocol-mode selection, fold-recovery-before-integrity-check startup ordering, interrupted-rewind completion, `--rewind-to-slot`, evidence-triggered store rewind in the recovery loop, verifier/fold/compaction config, and the engine doc (`docs/alpenglow_branch_engine.md`).
7. **Operator-focused terminal stats** — the 100-slot summary and per-slot lines rebuilt around the native-shred path (Agave `is_full` terminology): shred first/full timing, repair counts, latest-shred gaps, fork-switch outcomes, consensus/safety watermarks, promotion-hold signal; RPC-only mode fabricates nothing. Detailed debugging moved to file logs.
8. **Verifying/validator node modes + current defaults** — `consensus.mode = "verifying"` (default, non-voting) or Alpenglow-only `"validator"` (TPU ingress and block production active; voting still observer-only). Cluster defaults to and currently requires `alpenglow`; turbine is its default block source. `config init [--validator]` and the setup wizard generate per-mode configs.
9. **Repair-first catchup** — resume gaps up to `block.repair_catchup_max_gap_slots` (default 8192) fill via turbine repair instead of RPC `getBlock`: cryptographic finality from footer certs instead of delegated RPC trust, and the whole RPC budget stays with the trailing verifier. Generalizes the live-handoff machinery (runway parent-links from the resume block; assembler retention floor holds the window).
10. **Fork-choice hardening (review response)** — folds run async off the replay loop (single-flight worker; fork switches drain it; shutdown flushes through the same `min(finality, verified)` gate, with a proof test); stake-index appends are now slot-scoped/branch-safe (fold-time fsync'd flush BEFORE the batch commit, unwind drops wrong-fork entries); fork switches instrumented (in-RAM vs fallback with per-reason counts — the "do we need FD-style branching" signal); the sweep's decision oracles pinned by a scenario matrix, which exposed and fixed a real gap: cert-less ancestry-finalized blocks are now decisive and repairable (per-slot finalized index + hash-bound stub minting in the ancestry walk).

## What this PR adds — part 2: the shreds-only catchup engine (live-tested arc)

Everything after the ten core units was built and hardened **against live runs on the Alpenglow test cluster** (each fix diagnosed from real logs). End state: a **shreds-only node** — `block.rpc_fallback = false` by default, so turbine broadcast + repair are the ONLY block path at any distance from the tip; RPC serves only tip polling and the trailing verifier. These commits will be squashed into the logical units below.

11. **Catchup drive hardening** — the sequence of root-cause fixes that made shreds-only catchup actually run end-to-end: leader schedule built pre-block-source from manifest epoch stakes; fresh-boot runway anchor seeded from the resume slot (was a hard boot deadlock); TWO near-tip discard gates exempted for catchup/rescue deliveries (assembled blocks were silently destroyed at intake); certificate-skipped heads advance via the evidence-based skip oracle (skip certs or finalized ancestry, never parent-link inference); staging evicts highest-slot with completed-marker resets, and a stale marker on the waiting head heals via staged/buffered/lost classification with a persistence dampener; the live edge is bounded during catchup (far-future blocks stage instead of flooding the reorder buffer); handoff payload carries every staged block at/above the handoff slot, gaps included; a missing turbine slot pins repair and never triggers reconnect (the receiver is local state, not a connection).
12. **Turbine prewarm + frontier probe** — a receiver joins gossip/turbine at FULL-snapshot-manifest parse (minutes before the incremental in that flow; its epoch stakes usually already cover the live tip's schedule, and the incremental hook refreshes stakes so a running receiver self-heals). Every slot collected live during the AccountsDB build is a slot repair never fetches one-shred-per-round-trip. The prewarm also actively repairs the first 16 replay-frontier slots through the normal repair client (head-of-line stall time deleted from catchup), and its response statistics produce a boot-time rate recommendation at handover.
13. **On-disk shred spool** — verified shreds (data AND coding, so hydration self-heals holes via Reed-Solomon with zero network) write through to per-slot append files under the shredstore; 8GiB cap dropping highest slots; restart adoption; a hydrator prefetch-assembles a 256-slot window ahead of replay; a completeness journal (`complete.idx`) records proven-fully-assembled slots across restarts — the seed of a future repair-serving shredstore. The spool closes with its receiver so buffered tails always reach the next opener.
14. **Repair protocol pacing and selection** — the arc from "80% timeouts, self-inflicted" to cap-bound useful throughput: a 500 req/s token bucket (configurable, `block.repair_max_requests_per_second`) after peer-side serve-repair QoS froze an unbounded flood; FEC-deficit-aware request selection (a set holding coding needs only its deficit repaired — recovery yields the rest; cheapest-unlock-first ordering; cold sets unchanged); freshness-tiered priority/edge budgets with a demand-sized edge reserve; HighestWindowIndex followups metered from the same bucket (they bypassed it — 70% over-rate); adaptive request timeout (3× smoothed observed latency, clamped 1.5–6s) after fixed 1.5s re-requested shreds whose answers were queued; late answers matched from an expired-request memory and handled identically to timely ones (slot check, responder credit, gap followups, watchdog liveness); bounded 2-peer fanout for the emission-gating head; per-peer service records (timely/late/timeout/latency EWMA) driving a rolling quality score and responder-ranked selection (top half with a floor, 1-in-4 full-set exploration preserved).
15. **Sigverify efficiency** — shred signatures cache by (leader, merkle root, signature): the leader signs one root per FEC set, so ed25519 drops from one per shred to one per set (~64×) while the per-shred proof walk keeps tampered content structurally unable to hit the cache. Transaction sigverify moved from one goroutine per tx (30k spawns per big block) to a fixed GOMAXPROCS-aware pool with a bounded queue, and failure diagnostics (~10 base58 encodings per tx) render lazily instead of on the execution path.
16. **Operator observability** — chatty catchup status moved off the console into `catchup.log` in the per-run log directory (enriched with repair/hydration/sigverify counters); a `repair-peers` file logs the top peers' service records; per-slot shred timing is now replay-relative (`ready` = assembly-complete minus when replay asked, negative = pipeline ahead; `asm` = first shred → full); stall warnings carry full receiver drop counters, late/timeout split, and the effective adaptive timeout.
17. **Bootstrap UX** — snapshot source selection prefers the freshest incremental; `--bootstrap new-incremental` reuses the local full snapshot and fetches only a fresh incremental; the stale-snapshot prompt fires at 500 slots with a refresh-incremental-only option; UDP receive buffers request 64MiB/8MiB and print the sysctl remedy when the kernel clamps them.

## What this PR adds — part 3: AccountsDB V2 production candidate (eight logical units)

1. **Pebble-free account locations** — Pebble is removed from account lookup and update traffic; it remains only for the separate bank-hash database. Existing account indexes fail closed and require a fresh snapshot instead of silently selecting a compatibility path.
2. **Compact exact immutable base** — 1,024 keyed SipHash shards feed StreamHash bases with six-byte extent locators and one-byte fingerprints. A sorted full-key sidecar supports exact enumeration/rebuilds, and every base candidate is verified against the complete pubkey in its appendvec.
3. **Bounded exact mutable state** — CRC32C-framed WAL, exact StreamHash delta checkpoints, tombstones, multi-frame oversized folds, hard hot-key/byte/checkpoint budgets, and atomic WorkingSet admission prevent writes or valid large slots from turning into unbounded heap growth or partial publication.
4. **Online rolling maintenance** — largest-first concurrent checkpoint sealing and serialized per-shard rebases keep readers pinned to coherent generations. Retryable resource failures backpressure safely; format/integrity or ambiguous publication errors poison the index. Batched extent-prefix verification removes shard-count-multiplied publication work.
5. **Parallel account loading** — block keys are deduplicated, one mutable epoch and immutable generation are pinned, independent probes run over static worker ranges, and appendvec reads are sorted/coalesced before exact full-key verification. Loader and maintenance metrics expose where the block budget is spent.
6. **Verified bootstrap and fast reopen** — snapshot construction uses bounded external sorting, validates exact appendvec membership, capitalization and AccountsLtHash, preserves Alpenglow's exact block ID, and hands the verified immutable generation directly to the live runtime. Root-authenticated Linux sidecar receipts avoid a 38-byte-per-account startup rescan while stale identities fall back to full verification.
7. **Crash-safe appendvec lifecycle** — fold manifests are commit records, recovery and rewind fail closed, reader pins delay reclamation, and default-on pressure-gated compaction publishes relocation WAL state before retirement. Conservative disk admission includes fold output, relocation WAL/rewrite, metadata and reserve before any file-ID or output side effect.
8. **Production controls and evidence** — host-adaptive worker defaults, explicit memory/disk/FD limits, Nix and CLI wiring, startup validation, clean shutdown fencing, corruption/crash/race regressions, 30k-key benchmarks, and an operator acceptance guide turn the implementation into a monitored production candidate rather than an opaque benchmark prototype.

## Follow-ups: the road to a full Go validator

The fork-choice layer is voting-ready with **no mode split** — a voting engine plugs in above it via `CertPool.VerifiedVotorStakes` (kept trigger-fresh by the pool), the cert emit callback, and the tracker queries. End goal: everything in the node/validator natively in Go, with no Lightbringer dependency.

- **Voting**: Votor event loop + timeouts; BLS vote signing + all-to-all transmission; durable own-vote history before transmit (equivocation safety across restarts — the critical piece); standstill/cert-rebroadcast participation.
- **Repair serving**: repair exists as a tuned, cert-steered *client* (WindowIndex/HighestWindowIndex with pacing, scoring, and deficit-aware selection), and the on-disk shred spool with its completeness journal already delivers the store half (restart adoption, persist-during-build via prewarm, replaces Lightbringer's shredstore for catchup). Serving peers still needs the responder side: WindowIndex/HighestWindowIndex answered from the spool (lazy per-slot index→offset cache), the ping/pong challenge for unknown requesters, per-peer rate limits, and a serving-sized retention window. Serving also builds responder reputation with the exact peers whose QoS tiers throttle unstaked requesters.
- **Orphan requests — or an explicit decision we don't need them**: cert-driven steering substitutes for blind ancestry discovery in steady state (certificates name exactly the slots/blocks we're missing), but deep catchup-via-repair with no RPC (pure-cluster bootstrap) may still want them.
- **Block production follow-through**: versioned TPU transactions, producer-side epoch transitions/partitioned rewards, plus Rotor relay duty.
- **Background folding of sub-trigger tallies** for equivocation-evidence completeness (when slashing lands).
- **Pure-cluster execution oracle (transitional)**: consensus currently attests block data only, never execution — so a Mithril-only cluster needs peer bankhash cross-check (recommended — reuses the trailing-verifier evidence/halt path), finality-only promotion, or a retained external RPC oracle. Mixed clusters need nothing. This whole item dissolves once the protocol adds an execution commitment to the block footer: certificates would then attest executed state transitively, divergence becomes directly detectable against the footer, and the trailing verifier can retire with it.
