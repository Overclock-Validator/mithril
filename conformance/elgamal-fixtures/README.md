# ElGamal proof conformance

The reference is Agave commit
[`ffa314a0e10f48019cace790f633199a7c782024`](https://github.com/anza-xyz/agave/tree/ffa314a0e10f48019cace790f633199a7c782024),
whose Cargo.lock pins `solana-zk-sdk 8.0.1`. SDK source revision:
[`509d67bb656a61f1be121a66afebb4338401ffb0`](https://github.com/solana-program/zk-elgamal-proof/tree/509d67bb656a61f1be121a66afebb4338401ffb0).

`src/main.rs` ports the proof inputs from Agave's
[`programs/zk-elgamal-proof-tests/tests/process_transaction.rs`](https://github.com/anza-xyz/agave/blob/ffa314a0e10f48019cace790f633199a7c782024/programs/zk-elgamal-proof-tests/tests/process_transaction.rs).
The generated bytes **and acceptance results** come from the pinned Rust SDK.
The Go tests consume the checked-in JSON, requiring neither Rust nor network
access. Regeneration uses fresh randomness; the cases and their outcomes are
stable, but the proof bytes change.

From the repository root:

```sh
cargo run --locked --release --manifest-path conformance/elgamal-fixtures/Cargo.toml > /tmp/elgamal_agave_vectors.json
cp /tmp/elgamal_agave_vectors.json pkg/sealevel/testdata/elgamal_agave_vectors.json
go test ./pkg/sealevel ./pkg/replay -run 'TestElGamal|Test_ElGamal' -count=1
```

Only copy the output after cargo succeeds. The Cargo lockfile is checked in.
The generator also checks the historical Go fixtures against Rust before
retaining them as rejection regressions.

## Coverage

- Valid and invalid inputs from all eleven Agave proof-specific program tests,
  plus the SDK percentage-with-cap tests (including the alternative proof branch).
- All twelve proof types: inline and account-backed verification, context
  creation, reinitialization, close, authority aliases, wrong authorities,
  account sizes and owners, readonly contexts, and compute costs.
- Transaction-level rent exemption, insufficient rent, and creating, verifying,
  and closing a context within one transaction, for all twelve types.
- SDK-checked identity and noncanonical encoding mutations; absent auditor keys;
  identity destination ciphertext; one/eight-commitment batches; non-power-of-two
  range component widths; nonzero range padding; maximum-u64 percentage cap.
- Malformed instruction sizes/types, proof-account offsets, released account
  borrows, and disable/reenable feature behavior.
- The two actual public-key validity proofs rejected in testnet slot 447765040.

`pkg/sealevel/el_gamal_agave_test.go` ports the upstream generic program helpers
to Mithril's instruction runtime. `pkg/replay/el_gamal_rent_test.go` covers the
rent checks that occur outside the native program at the transaction boundary.
This is a port of the relevant upstream cases, not a run of Agave's entire Rust
program-test harness.

## Differences corrected

| Area | Correction to match the reference |
| --- | --- |
| Every proof transcript | Global `solana-zk-elgamal-proof-program-v1` domain, then instruction domain separation |
| Ciphertext/ciphertext equality | 192-byte context instead of 128 |
| Grouped validity, including batched | Append `z_r` before `z_x`; share the verification relation; preserve optional auditor semantics |
| Percentage with cap | Include `c_max_proof` before deriving the batching challenge |
| Identity points | Apply each proof's exact context/proof identity restrictions |
| Range proofs | Component widths 1 through 64, correct non-byte-aligned delta, zero context padding |
| Verification failures | Return `InvalidInstructionData` |
| Context creation | Ignore a lone extra account; validate metadata and sizes; release aliased borrows |
| Context close | Check owner, metadata, initialization, authority; release borrows on every return |
| Scalar conversion | Decode canonical scalars without unsafe layout casts |

The enabled program uses the current transcript exactly; it does not fall back
to accepting the obsolete transcript. The existing disable/reenable feature
gate remains in place.

## Saved testnet replay, 2026-10-03

Branch base: `2ea703dbb64498983d666062c262ab553d8f5bf4`
(`smcio/implement-vote-UpdateCommissionCollector`). The corrected implementation
was tested against the persisted parent 447765039 in `/mnt/mithril-testnet`.
Both Pebble databases were opened read-only; the original binary was preserved.

All ten captured transactions succeeded. Transactions 2 and 4 each consumed
10,704 CU instead of failing at 5,921 CU. Total consumption was 112,313 CU,
matching the saved testnet RPC result.

The bank-state reconstruction verified all 466 modified account-data SHA-256
values and the original accounts LtHash checksum, reproducing the original
incorrect bank hash:

```text

```

Replacing the payer and two newly created confidential token accounts with
their corrected execution results produced the exact expected footer hash:

```text

```

The original slot shreds/certificates were not retained. This is transaction
replay plus verified bank-state reconstruction, not a fresh replay of the
original shred/certificate pipeline. Only the captured failing slot 447765040
was available and verified.
